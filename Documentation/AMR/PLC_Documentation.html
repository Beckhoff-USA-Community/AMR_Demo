AMR Demo — PLC Documentation

TwinCAT 3 Structured Text  ·  IEC 61131-3  ·  PackML ISA-88

This document describes the high-level design of the PLC software for the AMR Demo BAUS — an Autonomous Mobile Robot demonstration built on the Beckhoff TwinCAT 3 automation platform. The PLC controls two differential-drive wheels, a lift axis, communicates with the Navitrol navigation supervisor over TCP/IP, and integrates a TwinCAT Safety system with two laser scanners.

Project file Open AMR_Demo/AMR_Demo.sln in Visual Studio. PLC project is at AMR_Demo/PLC/PLC.plcproj. Task: PlcTask, Priority 20, 20 ms cycle (50 Hz), AMS Port 350.

Execution Flow

MAIN.TcPOU is the only PLC program and is the sole entry point called by PlcTask.

PROGRAM MAIN
VAR
    Simulated              : BOOL := FALSE;
    AmrModule              : AmrModule('AMR Module');
    MachineHmiTree         : GetSystemTreeJsonHmiVisitor<1000>('MAIN');
    SetSafetySimulationVisitor : SetSafetySimulationVisitor;
END_VAR

// First cycle only — initialise module and build HMI tree
IF NOT AmrModule.Initialized THEN
    AmrModule.Initialize();
    MachineHmiTree.GetTree(AmrModule);
    IF Simulated THEN
        SetSafetySimulationVisitor.State := 1;
        AmrModule.Components.Accept(SetSafetySimulationVisitor);
    END_IF
    RETURN;
END_IF

// Every subsequent cycle
AmrModule.CyclicLogic();

Setting Simulated := TRUE bypasses physical safety hardware — all safety components accept a simulated-OK state, allowing development without the robot.

Keep outputs on breakpoint _AppInfo.KeepOutputsOnBP := TRUE is set at the top of MAIN so that NC drives keep their last commanded velocity when a TwinCAT breakpoint is hit.

AmrModule

AmrModule EXTENDS PackMLModule IMPLEMENTS I_AmrModule — the central function block that owns every subsystem. It lives in MAIN as a single instance and is the root of the component tree.

StateBadgeDescription
Stopped Idle All axes disabled. Manual axis control via HMI is available. No automatic operation.
Starting Transition Initialises Navitrol pose (x=21.23, y=36.92, θ=90°), enables all 3 axes, enables velocity streaming, moves lift to LiftPosition_Down.
Execute Running Autonomous operation. Cycles waypoints 1–4, raises/lowers lift at each stop. Immediately triggers Suspend if either scanner is obstructed (and BypassScanners = FALSE).
Stopping Transition Waits for Navitrol setpoints and wheel velocities to reach zero, then disables streaming and all axes gracefully.
Aborting Emergency Immediately disables streaming, halts wheels (MC_Halt), stops lift, disables all axes.
Aborted Fault Robot is idle. All axes disabled. Operator must issue Reset command to transition to Clearing.
Clearing Transition Safety reset sequence: pulse SafetyReset → 200 ms delay → ELM reset → ResetComponents() → release E-Stop in Msg3002.
Suspending Safety Sets E-Stop in Navitrol, stops lift, waits for all motion to halt, disables axes.
Suspended Safety Waits. Automatically transitions to Unsuspending when both SafetyScannerLeuze.OK and SafetyScannerHokuyo.OK.
Unsuspending Safety Resets both scanner faults, 200 ms delay, ELM reset, re-enables axes, releases E-Stop, moves lift to down, re-sends GoToDestination to resume route.

State Sequences

Each state method contains a CASE SequenceState OF block. NextStep() advances to the next multiple of 10; NextMinorStep() increments by 1 (for sub-steps within a step). A state method signals completion by returning TRUE.

Send Msg1001 InitializePosition (x=21.23, y=36.92, θ=90°, level=0). Set Destination := 1.
1
Wait for Navitrol state = STANDBY, HOLD, or AUTO.
10
Enable WheelLeft, WheelRight, Lift axes. Wait until all Enabled.
20
Enable WheelLeft_StreamVelocity and WheelRight_StreamVelocity. Wait until both Enabled.
30
Lift.MoveAbsolute(Recipe_HMI.LiftPosition_Down).
31
Wait until lift not Busy, no Error, and position within 0.1 mm of target.
40
Return Starting := TRUE → transition to Execute.

0

10
Send Msg3005 GoToDestination(Destination).
11

20
Lift.MoveAbsolute(Recipe_HMI.LiftPosition_Up).
21
Wait until lift at LiftPosition_Up ± 0.1 mm.
30
Wait 5 s (dwell time at destination).
40
Lift.MoveAbsolute(Recipe_HMI.LiftPosition_Down).
41
Wait until lift at LiftPosition_Down ± 0.1 mm.
50

20

30

E-Stop integration

The PLC signals an E-Stop to Navitrol by setting Navitrol_Status.SupervisorStatus.Set_Estop := E_3002_Set_ESTOP.Set_ESTOP (carried in the next Msg3002 send). This is done in three cases:

  • AmrEvents(): when SafetyEstop.OK = FALSE (hardware E-Stop active)
  • Suspending: when a scanner obstruction is detected

E-Stop is released by setting Release_ESTOP during Clearing (step 30) and Unsuspending (step 10).

Velocity Streaming

Navitrol_StreamVelocity (PLC/Components/Navitrol/Navitrol_StreamVelocity.TcPOU) drives a wheel axis at a continuously-updated velocity setpoint received from Navitrol.

Design

  • Dual MC_MoveVelocity toggle: holds two MC_MoveVelocity instances (A and B). Each cycle, the inactive FB is executed with the new setpoint and buffer mode MC_Aborting, then the active/inactive roles are swapped. This gives seamless setpoint changes without any stop-and-restart.
  • PT1 smoothing filter: an optional first-order low-pass filter (FilterTimeConstant := T#100MS) softens sudden changes from Navitrol. Toggled via EnableSmoothing.
  • Stop on zero: when |setpoint| < VelocityTolerance, an MC_Halt is issued instead of a zero-velocity MoveVelocity.

Unit Conversion

Navitrol provides wheel velocity in m/s. The NC axis expects °/s (because wheel rotation is tracked in degrees). The conversion is applied in OnCyclicCall: 

// (Diameter Wheel * 360°) circumference → angular velocity
_WheelLeft_StreamVelocity.SetTargetVelocity(
    (360 * SetPointSpeedLeft) / (PI * AMR_CONSTANT.WHEEL_DIAMETER)
);
// WHEEL_DIAMETER = 0.160 m  →  at 1 m/s ≈ 716 °/s

Odometry goes the other way — wheel position in degrees × 1000 is sent as milli-degrees:

EncoderCountWheelLeft := TO_UDINT(_WheelLeft.ActualPosition * 1_000);

Reset Sequence

200 ms delay is mandatory The delay between pulsing SafetyReset and executing SafetyResetELM is required for the safety signals to propagate through the ELM drive modules before the drive reset is attempted. Removing or shortening this delay may cause the reset to fail.
1

2

3

4

5
Release E-Stop flag in Navitrol (Msg3002)

BypassScanners

The HMI can set BypassScanners := TRUE (via ST_AmrModule_HMI) to prevent the scanner obstruction check in Execute from triggering a Suspend. A physical output _BypassScanners AT %Q* mirrors this to hardware. Default is TRUE (bypass enabled).

Encoder

An external encoder (Mouser DHK / BEI DHx5, IO-Link) provides position and speed feedback independent of the NC axes (used for odometry verification or display).

  • EncoderSpeedIn AT %I* : INT — raw analog speed input
  • EncoderPositionIn AT %I* : INT — raw analog position input
  • EncoderSpeed / EncoderPosition : AnalogInput — scaled engineering unit values
  • Encoder_HMI — exposes scaled values and scaling configuration to HMI

Scaling parameters (InputMin/Max, OutputMin/Max for both speed and position) are configured via the HMI and applied every cycle in OnCyclicCall.

Key Patterns

RegisterWithParent

Every subsystem (axes, Navitrol FBs, safety groups, encoder, HMI FBs) calls RegisterWithParent(THIS^) in FB_Init. This registers the component in the parent's component tree, enabling:

  • Visitor-based operations: ResetComponents(), SetAllOverrideVisitor, HmiEnableDisableAllVisitor, GetSystemTreeJsonHmiVisitor
  • Recursive CyclicLogic() dispatch
  • Automatic HMI symbol tree construction

Adding a new component: declare it as a member variable, call MyComponent.RegisterWithParent(THIS^) in FB_Init. It will then automatically participate in all visitor operations.

SequenceState / NextStep / NextMinorStep

State transition methods use a numbered CASE SequenceState OF pattern. Steps are multiples of 10 (for main steps) with +1 increments (for minor sub-steps). This convention reserves room to insert intermediate steps without renumbering. 

CASE SequenceState OF
    0:  // first step
        DoSomething();
        NextStep(SequenceState);        // → 10

    10: // second step
        StartAsyncOp();
        NextMinorStep(SequenceState);   // → 11

    11: // wait for async op
        IF AsyncOpDone THEN
            NextStep(SequenceState);    // → 20
        END_IF

    20: // completion
        MyState := TRUE;              // signal PackML to advance
END_CASE
