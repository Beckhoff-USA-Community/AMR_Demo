AMR Demo BAUS

Autonomous Mobile Robot demonstration — Beckhoff TwinCAT 3

A complete AMR system integrating real-time motion control for a differential-drive robot, TCP/IP navigation via Navitrol, functional safety with TwinCAT Safety, and a web-based HMI. Control logic follows the ISA-88 PackML state machine pattern.

Building & Running

Prerequisites

  • TwinCAT 3.1 Build 4026.20 or later
  • Visual Studio 2015 or later with TwinCAT XAE Shell
  • TwinCAT HMI Server (TE2000) for HMI

PLC / Safety

  1. Open AMR_Demo/AMR_Demo.sln in Visual Studio
  2. Right-click PLC or Safety project → Build
  3. Deploy: TwinCAT → Activate Configuration

HMI

  1. Open AMR_Demo_HMI/AMR_Demo_HMI.sln
  2. Build → Build Solution (F6) — output to HmiProj/bin/
  3. Start TwinCAT HMI Server, access at http://localhost:1010
Simulation mode (no hardware): Set Simulated := TRUE in AMR_Demo/PLC/MAIN.TcPOU to bypass physical safety hardware via SetSafetySimulationVisitor.

Execution Flow

MAIN.TcPOU is the sole PLC entry point. On the first cycle it calls AmrModule.Initialize() and MachineHmiTree.GetTree(AmrModule) to build the HMI symbol tree, then every subsequent cycle calls AmrModule.CyclicLogic().

AmrModule EXTENDS PackMLModule owns all subsystems as member variables registered via RegisterWithParent(). The cyclic call propagates through every registered component automatically.

PackML State Machine

Two modes: Production and Manual. Mode changes are allowed from Stopped and Aborted.

stateDiagram-v2 [*] --> Aborted Aborted --> Clearing : Reset Clearing --> Stopped Stopped --> Starting : Start Starting --> Execute Execute --> Stopping : Stop Stopping --> Stopped Execute --> Suspending : Scanner obstructed Suspending --> Suspended Suspended --> Unsuspending : Scanner cleared Unsuspending --> Execute Execute --> Aborting : Abort Stopping --> Aborting : Abort Aborting --> Aborted
  • StoppedIdle; no active motion. Manual axis control allowed via HMI.
  • StartingInitialize Navitrol position (x=21.23 m, y=36.92 m, θ=90°), enable axes, enable velocity streaming, move lift to down position.
  • ExecuteCycles destinations 1→4, streams Navitrol velocity to wheel axes, raises/lowers lift at each stop. Triggers Suspend immediately if either scanner is obstructed.
  • StoppingWaits for velocity setpoints to reach zero and wheels to stop, then disables streaming and disables all axes.
  • AbortingEmergency: immediately disables velocity streaming, stops wheels, stops lift, disables all axes.
  • AbortedFault state; all axes disabled. Operator must issue Reset.
  • ClearingPulse SafetyResetPulse → wait 200 ms → ResetComponents() → release E-Stop in Msg3002.
  • SuspendingSet E-Stop flag in Navitrol, stop lift, disable axes.
  • SuspendedWaits until both SafetyScannerLeuze and SafetyScannerHokuyo report OK.
  • UnsuspendingReset scanner faults, re-enable axes, release E-Stop, move lift down, re-send GoToDestination.

Navitrol Communication

TCP/IP connection to 127.0.0.1:2000. All message function blocks extend TcpIpCommandResultFilter and share a single TcpIpConnection instance.

Function BlockSendsReceivesIntervalPurpose
Msg3002_NavitrolStatus 30023102100 ms Bidirectional status; carries E-Stop flag and robot pose
Msg1001_InitializePosition 10011100 / 1101On demand Set initial robot pose (X, Y, heading, level)
Msg1016_MeasurmentUpdateDifferentialDrive 10161116 30 ms Upload encoder odometry; receive wheel velocity setpoints
Msg3005_GoToDestination 30053105On demand Command navigation to a waypoint by ID
Msg3024_ReturnToRoute 30243124On demand Resume interrupted route
Msg3001_HoldRelease 30013101On demand Hold / release motion
Critical timing: Msg1016 cycle time (30 ms) must match the Navitrol parameter control_interval_us.

Velocity Conversion

Navitrol provides wheel speed in m/s. NC axes use °/s. Conversion applied in OnCyclicCall:

ω (°/s) = (360 × v) / (π × WHEEL_DIAMETER)   // WHEEL_DIAMETER = 0.160 m

Velocity Streaming — Navitrol_StreamVelocity

Drives each wheel via two alternating MC_MoveVelocity instances with MC_Aborting buffer mode, allowing smooth setpoint changes every cycle. An optional PT1 first-order filter (τ = 100 ms, toggled via EnableSmoothing) smooths velocity transitions. Stops via MC_Halt when |velocity| < VelocityTolerance.

Safety System

Safety signals flow through SafetyGroup_TcEvents groups with AutoResetFaults := TRUE.

Function BlockTypeGroupEffect
SafetyEstop SafetyEstopFB_TcEvents SafetyInputGroup Sets Set_Estop flag in Msg3002
SafetyScannerLeuze SafetyMonFB_TcEvents SafetyInputGroup Triggers Suspend from Execute
SafetyScannerHokuyo SafetyMonFB_TcEvents SafetyInputGroup Triggers Suspend from Execute

Three safety groups are registered:

  • SafetyInputGroup — E-Stop and scanner inputs
  • SafetyMotionGroup — Drive motion safety
  • SafetyLiftSpeedGroup — Lift speed monitoring

Reset Sequence (Clearing state)

SafetyResetPulse → 200 ms delay → ResetComponents() → Release E-Stop in Msg3002
